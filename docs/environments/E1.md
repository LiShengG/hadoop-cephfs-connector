# E1 development environment

> Last verified: 2026-08-14

## Purpose

E1 is the single-node development environment for JNI smoke checks, fast contract/integration
regression, CLI validation, and packaging. It does not provide redundancy, production failure
behavior, performance baselines, or multi-tenant evidence.

## Topology and versions

| Item | Definition |
|---|---|
| Host role | One development host running Ceph daemons and the connector tests |
| Ceph | Pacific 16.2.14 debug build |
| CephFS | One active MDS and test pools with replication size 1 |
| OSD | Four local test OSDs in the latest recorded environment |
| Java | OpenJDK 11 baseline |
| Hadoop | 3.3.6 build/test dependency |
| Authentication | Development-only admin identity |

The exact 2026-08-14 execution result is in
[`2026-08-14-e1-regression.md`](../reports/2026-08-14-e1-regression.md).

## Required variables

Set paths for the local Ceph build rather than embedding a user-specific path in commands:

```bash
export CEPH_BUILD=/path/to/ceph/build
export CEPH_CONF_FILE="$CEPH_BUILD/ceph.conf"
```

The repository scripts derive the connector root from their own location. `CEPH_BUILD` overrides the
external Ceph build directory where supported.

## Native artifacts

The following files must be generated from the same Ceph source/build and copied to `dist/native/`:

- `libcephfs.jar`
- `libcephfs_jni.so`

If the Ceph build was configured with its Java binding enabled, rebuild the two explicit targets:

```bash
CONNECTOR_ROOT="$(pwd)"
cd "$CEPH_BUILD"
make libcephfs cephfs_jni
cp src/java/libcephfs.jar "$CONNECTOR_ROOT/dist/native/libcephfs.jar"
cp lib/libcephfs_jni.so.1.0.0 "$CONNECTOR_ROOT/dist/native/libcephfs_jni.so"
```

The upstream meta target named `java` was not usable in the recorded Pacific build. Use the explicit
targets above.

## Status and validation commands

```bash
scripts/cluster-up.sh
scripts/smoke-test.sh
cd hadoop-cephfs
mvn -B clean test
CEPH_CONTRACT_TEST=1 mvn -B verify
```

`scripts/cluster-down.sh` stops this development cluster. Do not use either lifecycle script against
E2 or E3.

## Safety constraints

- E1 data is disposable, but the external Ceph source tree is not part of this repository and must
  not be modified to implement connector tasks.
- The size-1 pools can report a no-replica health warning. Do not treat E1 as durability evidence.
- Do not copy the development admin credential or debug-library settings into deployment guidance.
- Confirm `CEPH_BUILD` before starting or stopping daemons.

## Rebuild entry point

The cluster scripts wrap the recorded vstart workflow. A rebuild that uses a new-cluster option
destroys E1 test data; run it only when the test-owned environment may be reset.
