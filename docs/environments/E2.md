# E2 three-node CephFS environment

> Last verified: 2026-08-15

## Purpose

E2 is the production-shape CephFS test environment for release-client contract tests, minimum-cephx
checks, failure injection, performance work, and soak preparation. Test data is disposable, but disk
selection is safety-critical.

## Topology and versions

| Item | Definition |
|---|---|
| Nodes | `node-44` (`10.20.40.44`), `node-26` (`10.20.40.26`), `node-28` (`10.20.40.28`) |
| Public network | `10.20.40.0/23` on `ens192` |
| Cluster network | `172.30.40.0/24` on `ens224` |
| Ceph service | Pacific 16.2.14 release container |
| Control plane | 3 MON, 2 MGR |
| Storage | 6 OSD, two per node, host failure domain |
| CephFS | `cephfs-e2`, 3 MDS with one active and two standby |
| Pools | Metadata and data pools use `size=3`, `min_size=2` |
| Client | `client.hadoop`, restricted to `cephfs-e2` |
| Client files | `/etc/ceph/ceph.conf`, `/etc/ceph/ceph.client.hadoop.keyring` |

The recorded filesystem ID, image digest, client patch version, commands, and results belong to
[`2026-08-15-e2-release-regression.md`](../reports/2026-08-15-e2-release-regression.md).

## Storage devices

Only these devices belong to E2:

| Node | E2 devices |
|---|---|
| `node-44` | `/dev/sdb`, `/dev/sdc` |
| `node-26` | `/dev/sdc`, `/dev/sdd` |
| `node-28` | `/dev/sdd`, `/dev/sdg` |

The following `node-28` devices contain unrelated BlueStore data and are excluded:

```text
/dev/sdb /dev/sdc /dev/sde /dev/sdf
```

## Safety constraints

- Never use `--all-available-devices`.
- Never zap, repartition, format, or redeploy an OSD without resolving the node and exact device
  against the allowlist above.
- Never operate on the excluded `node-28` devices.
- Do not destroy E2 to satisfy an individual test. Failure injection must name its target and recovery
  condition.
- Use the restricted `client.hadoop`; do not substitute an admin identity for a passing test.

## Network and ports

Nodes require the public and cluster networks above, SSH for controlled administration, and Ceph
monitor/manager/OSD/MDS connectivity. The environment also supplies the CephFS backend used by E3.
Changes to shared network identity require coordination with the E3 owner.

## Status command

Run the repository's read-only check on `node-44`:

```bash
scripts/env/e2-status.sh
```

The command must report 3 monitors, 6 OSDs up/in, the configured pool replica settings, and
`HEALTH_OK`. A report records the exact output; this environment definition does not.

## Rebuild entry point

A repeatable from-zero E2 provisioning script is not yet tracked. This is a T08 blocker. Until that
exists, preserve the current cluster and use only the read-only status command unless the active task
explicitly authorizes a scoped environment change.
