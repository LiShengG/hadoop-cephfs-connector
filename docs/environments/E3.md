# E3 Hadoop ecosystem environment

> Last verified: 2026-08-15

## Purpose

E3 validates the connector through real Hadoop/YARN ecosystem processes. It reuses E2's CephFS and
three nodes; HDFS remains available for mixed-filesystem scenarios. Test outcomes are stored in
[reports/](../reports/).

## Topology and versions

| Item | Definition |
|---|---|
| Nodes | `node-44` (`10.20.40.44`), `node-26` (`10.20.40.26`), `node-28` (`10.20.40.28`) |
| Java | OpenJDK 11 |
| Hadoop | Apache Hadoop 3.3.6 |
| Spark | Apache Spark 3.4.4 |
| Hive | Apache Hive 4.0.1 with an embedded test metastore |
| Tez | Apache Tez 0.10.4 |
| Service user | `hadoope3`, UID/GID 2001 on all nodes |
| Master roles | NameNode, ResourceManager, and JobHistoryServer on `node-44` |
| Worker roles | One DataNode and NodeManager on each node |
| HDFS | NameNode RPC `10.20.40.44:8020`, three DataNodes, default replication 2 |
| CephFS | E2 `cephfs-e2`, restricted client identity, `/e3` test root |

Tracked Hadoop/Hive/Tez configuration templates are in [`conf/e3/`](../../conf/e3/).

## Services and ports

| Service | Endpoint |
|---|---|
| NameNode RPC | `8020` |
| NameNode web | `9870` |
| ResourceManager RPC | `8032` |
| ResourceManager web | `8088` |
| JobHistoryServer RPC | `10020` |
| JobHistoryServer web | `19888` |

Local service state is under `/var/lib/hadoop-e3`; service logs are under `/var/log/hadoop-e3`.
CephFS service paths include YARN logs, job history, staging, Spark event logs/checkpoints, and test
data beneath `/e3`.

## Client deployment

- The connector jar and `libcephfs.jar` are installed in the Hadoop common library location on all
  nodes.
- The keyring is owned by `root:hadoope3`, mode `0640`, on each node.
- Container JVMs receive the release JNI path and its native loader directories.
- `HADOOP_MAPRED_HOME` is set for MR application master, map, and reduce containers.
- Tez uses its runtime archive and adds the connector/Java binding to the cluster classpath.
- When HDFS is the default filesystem, Ceph paths use an explicit authority; see
  [LIM-008](../KNOWN-LIMITATIONS.md#lim-008-mixed-default-filesystem-requires-explicit-ceph-authority).

## Safety constraints

- E3 shares E2's CephFS and therefore inherits every E2 disk and cluster safety constraint.
- Do not switch the current cluster to Kerberos in place. Security tests require an isolated
  environment and rollback plan.
- Do not evict a CephFS session until its client PID is absent and in-flight activity has been checked.
- Do not bulk-evict sessions belonging to NodeManagers, the history server, or other live services.
- Use the cephadm container's matching Ceph CLI for cluster management; an incomplete experimental
  CLI exists on one worker and is not an administration entry point.

## Current environment blockers

- `node-26` has previously appeared with a conflicting MAC address and SSH identity. `node-44` has a
  runtime neighbor workaround; the durable fix belongs to the network/virtualization owner.
- The monitor store on `node-44` has shown high tail latency and election instability. A runtime
  lease adjustment was used for testing but is not persistent and slows failure detection. The store
  requires lower-latency placement before reliability testing.
- Client versions are not uniform across every node. The observed combination is evidence for one
  baseline only, not the compatibility matrix.

## Status command

Run the read-only check on `node-44`:

```bash
scripts/env/e3-status.sh
```

It checks three live DataNodes, three running NodeManagers, and the NameNode, ResourceManager, and
JobHistoryServer endpoints.

## Rebuild entry point

A complete one-command E3 rebuild is not tracked. Configuration templates and the read-only status
script are available, but repeatable provisioning remains a T08 exit criterion.
