# T06 — Hadoop 契约测试与端到端集成验证

## 目标

用 Hadoop 官方 FileSystem 契约测试套件系统性验证语义正确性，修复暴露的缺口，
并完成 `hadoop fs` CLI 全链路验证。这是质量收口任务。

## 前置依赖

T05 DONE。必读：架构文档 §4、§6.2；
参考：`hadoop-3.3.6-src/hadoop-common-project/hadoop-common/src/test/java/org/apache/hadoop/fs/contract/`
（`AbstractFSContract*`、`localfs` 契约实现与 `contract/localfs.xml` 范例）。

## 工作内容

1. **契约声明** `src/test/resources/contract/ceph.xml`：逐项声明能力
   （`supports-append=true`、`supports-atomic-rename`、`supports-block-locality=true`、
   `supports-concat=false`、`supports-seek=true`、`rename-overwrites-dest=false`、
   `supports-unix-permissions=true` 等，以实测为准）。
2. **契约测试类**：`CephFSContract extends AbstractBondedFSContract`（或
   `AbstractFSContract`，参照 localfs 写法），并派生标准套件（均门控）：
   `ITestCephContractCreate / Open / Rename / Delete / Mkdir / Seek / Append /
   RootDirectory / GetFileStatus`。
3. **跑测与修复**：迭代运行契约套件，修复暴露的语义缺口（预计集中在
   rename 边界、create 父目录检查、seek 越界异常类型）。每个排除的用例必须在
   ceph.xml 或 override 方法中给出书面理由（写入代码注释 + PROGRESS.md）。
4. **CLI 端到端** `scripts/e2e-cli-test.sh`：
   - 组装运行时 classpath（Hadoop 3.3.6 发行版可用 `hadoop-3.3.6-src` 构建产物或
     仅用 hadoop-common jar + `hadoop fs` 等效的 `org.apache.hadoop.fs.FsShell` 直跑，
     取最省事可行的方式，写清楚）；
   - 覆盖：`-mkdir -p`、`-put`（≥200MB 文件）、`-ls`、`-cat`、`-cp`、`-mv`、
     `-rm -r`、`-df`、`-stat`，逐条断言退出码与输出；put/get 往返 md5 比对。
5. **并发冒烟**：4 线程并发各写/读独立文件（可以是 JUnit 集成测试），
   验证共享 mount 无死锁/数据错乱。

## 交付物

- `contract/ceph.xml`、`CephFSContract.java`、9 个契约测试类
- `scripts/e2e-cli-test.sh`
- 修复涉及的源码变更（每处在 PROGRESS.md 说明）
- PROGRESS.md：契约测试结果汇总表（通过/排除/理由）

## 验收标准

1. `CEPH_CONTRACT_TEST=1` 下全部契约测试通过（排除项均有书面理由且数量 ≤ 5 类）；
2. `scripts/e2e-cli-test.sh` 退出码 0，md5 往返一致；
3. 并发冒烟通过；
4. `mvn clean test`（无集群）依旧绿色——契约套件正确 skip。

## 边界与禁止事项

- 修复以满足契约为限，不做重构/性能优化；
- 改动 T02 冻结接口需先登记（预期不需要）；
- 不做打包与部署文档（T07）。
