# T07 — 打包、部署与使用文档

## 目标

产出可交付的部署包与用户文档，使第三方在一台装有 Hadoop 3.3.6 与 Ceph 客户端库的
机器上，按文档 30 分钟内配通 `ceph://`。

## 前置依赖

T06 DONE。必读：架构文档 §5、§6.1、§8-M6。

## 工作内容

1. **打包**：
   - `mvn package` 产出 `hadoop-cephfs-1.0.0.jar`（不 shade Hadoop；
     `libcephfs.jar` 是否合入二选一并说明理由——建议不合入、并列发布）；
   - `scripts/make-dist.sh`：一键产出
     `dist/hadoop-cephfs-1.0.0/{hadoop-cephfs-1.0.0.jar, libcephfs.jar,
     libcephfs_jni.so, conf/core-site.xml.example, README}`
     的 tar.gz。
2. **配置样例** `conf/core-site.xml.example`：含 §5 全部键的注释版，
   分别给出 vstart 本机版与生产集群版两组示例值。
3. **用户文档** `docs/DEPLOY.md`：
   - 前提条件（Java、Hadoop 3.3.6、libcephfs.so 的获取方式）；
   - 安装步骤：jar 放入 `$HADOOP_HOME/share/hadoop/common/lib/`（或
     `HADOOP_CLASSPATH`），native 库路径三种配置方式
     （`LD_LIBRARY_PATH` / `JAVA_LIBRARY_PATH` / `hadoop-env.sh`）；
   - core-site.xml 配置讲解、cephx 权限要求（client 需要 mon r + mds rw + osd rw）；
   - 验证命令序列与常见故障排查表（UnsatisfiedLinkError、mount 超时、
     权限拒绝 各给出症状→原因→解法）。
4. **开发者文档** `docs/DEVELOP.md`：构建、测试分级（单测/契约/E2E）的运行方法，
   直接引用现有 scripts。
5. **终验**：开新 shell（不继承会话环境），仅按 DEPLOY.md 步骤操作，
   完成 `hadoop fs -ls / -put / -cat / -rm ceph:///...`（FsShell 等效方式亦可，
   与 T06 CLI 方案保持一致），录制命令与输出附于 PROGRESS.md。
6. **收尾**：更新根 README.md 的状态与快速上手段落；`git tag v1.0.0`。

## 交付物

- `dist/hadoop-cephfs-1.0.0.tar.gz` 与 `scripts/make-dist.sh`
- `conf/core-site.xml.example`、`docs/DEPLOY.md`、`docs/DEVELOP.md`
- 更新后的 README.md、git tag `v1.0.0`

## 验收标准

1. `scripts/make-dist.sh` 从干净 `mvn clean` 状态一键成功；
2. 终验（干净 shell、只按文档操作）全部命令成功，记录在 PROGRESS.md；
3. DEPLOY.md 中每条命令均实测有效，无"应该可以"式表述；
4. 排查表覆盖至少 3 类真实复现过的故障。

## 边界与禁止事项

- 不新增功能、不重构；发现缺陷仅登记（严重阻断性缺陷除外，修复后补跑 T06 相关用例）；
- 不发布到任何外部仓库（Maven Central 等）。
