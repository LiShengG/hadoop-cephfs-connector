# T12 — 安全、长稳与发布验收

## 目标

收口生产就绪：完成安全与多租户模型的实测与书面澄清、72 小时长稳与泄漏验证、
部署运维验收，并按 TEST-PLAN §13 的准出标准组织发布评审，产出可签署的
《生产就绪报告》。

## 前置依赖

T08–T11 全部 DONE，且 S1/S2 缺陷已清零。必读：`docs/TEST-PLAN.md` §8、§10、
§13、附录 A；`docs/TEST-CASES.md` SOAK-*/SEC-*/OPS-* 三节。

## 工作内容

1. **安全与多租户**（SEC-01–SEC-10）：
   - **SEC-01 身份模型澄清（最高优先级）**：连接器所有请求使用同一 cephx id，
     Hadoop UGI 身份不下传 MDS —— 用多 UGI 对照实测证明，并在 DEPLOY.md 新增
     **《安全模型与适用边界》**章节，明确写出"CephFS 侧无法按 Hadoop 用户鉴权"
     及其对多租户场景的含义与规避方式（每租户独立 cephx 用户 + `ceph.root.dir`）；
   - 最小 caps 矩阵、路径受限 caps、root_squash、子目录挂载隔离性；
   - **密钥泄漏自动断言**：对全部测试日志 grep cephx key 特征，0 命中；
   - `setOwner` 非数字静默 warn、`mode & 01777` 丢弃 setuid/setgid 两项差异
     写入"已知限制"。
2. **长稳**（SOAK-01–SOAK-05）：
   - `scripts/soak/run-soak.sh`：72h 混合负载（读写 7:3 + 元数据 + 每 6h 轮转
     故障注入 F01/F03/F07 + 每小时 md5 抽样）；
   - `scripts/soak/monitor.sh`：60s 粒度采集 JVM heap、**native RSS/NMT**、线程数、
     `/proc/<pid>/fd` 计数、CephFS 会话数、慢请求、OSD/MDS 延迟，产出趋势图；
   - 专项：`CephFs`（AbstractFileSystem）无 close 钩子导致的 mount 生命周期问题，
     用 24h FileContext 长跑量化（呼应 T11 的 YARN NM 观测）。
3. **部署与运维验收**（OPS-01–OPS-10）：真实发行版安装、native 三种配置方式、
   1.0.0 ↔ 1.1.0 升级回滚、混版滚动更新、排查表在生产构建上的复现、
   监控采集点方案、制品可重现性与 so 纯净度（收口 T07 遗留 2/3）、干净 shell 终验重跑。
4. **非目标可诊断性**（NEG-01–NEG-08）：确保每个"不支持"都以明确异常与可读消息失败。
5. **附录 A 逐项结论**：8 项待决项每项给出 修复 / 文档化为已知限制 / 延期（含触发条件）
   三选一，并附依据。需要代码增强的，产出独立任务书草案（不实现）。
6. **发布评审**：按 §2 阈值逐条判定，产出
   `docs/RELEASE-READINESS-1.1.0.md`（结论、证据链接、未决风险、豁免记录、签署栏），
   并更新 README 状态与文档导航。

## 验收标准

1. SEC-01–SEC-10 全部执行；密钥泄漏 grep 断言 0 命中；安全模型章节经复核，
   对"多租户如何隔离"给出可操作方案；
2. 72h 长稳一次性跑完（中断需重跑）：0 失败、每小时 md5 抽样一致、
   native RSS 增长 < 5%/24h、fd 归零、线程数与会话数稳态；
3. OPS-01–OPS-10 全部通过，其中 OPS-01 必须使用**真实 Hadoop 发行版**；
4. NEG-01–NEG-08 全部为"明确异常 + 可读消息"，无静默成功或 NPE；
5. TEST-PLAN §2 全部阈值逐条判定完毕；S1/S2 为 0；每个未达标项要么已修复复测，
   要么有评审通过的书面豁免；
6. `docs/RELEASE-READINESS-1.1.0.md` 完成并可被第三方按其证据链接复核。

## 边界与禁止事项

- 不实现附录 A 的代码增强（仅产出结论与任务书草案）；
- 72h 长稳期间 E2 独占，不并行跑性能或生态用例；
- 发布制品的对外分发渠道与签名流程需人工决策，本任务只产出要求与检查项；
- 未达标项不得"降低阈值"了事——阈值调整须走发布评审并记录理由。
