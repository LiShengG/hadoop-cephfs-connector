# T08 — 测试基础设施与质量门禁

## 目标

把 v1.0.0 的"开发机手工验证"升级为可复现、可自动执行的工程化测试底座：
生产仿真集群与 Hadoop 生态集群的一键供给、CI 流水线、静态与覆盖率门禁，
并用 Hadoop 官方基类套件把契约层覆盖面（尤其 `FileContext`/`CephFs` 路径）扩到位。
本阶段是 T09–T12 的硬前置。

## 前置依赖

v1.0.0 已发布（T07 DONE）。必读：`docs/TEST-PLAN.md`（尤其 §4 环境矩阵、§5 L0–L2、
§12 CI）、`docs/TEST-CASES.md` 的 UT-*/CT-* 两节、架构文档 §6.2、`docs/ENV.md`。

## 工作内容

1. **E2 生产仿真 Ceph 集群供给** `scripts/env/ceph-cluster-up.sh` / `-down.sh`：
   ≥ 3 节点、3 mon / 2 mgr / 3 mds（1 active + 2 standby）/ ≥ 6 osd、
   replicated size=3 min_size=2、**非调试构建**（验证 lockdep workaround 不再需要）、
   按最小权限创建测试 cephx 用户；脚本须幂等、内置健康等待、支持一键销毁重建。
   同时产出 `scripts/env/fingerprint.sh`：采集并归档环境指纹
   （`ceph versions`/`osd tree`/`config dump`/内核/JDK/Hadoop/连接器 commit）。
2. **E3 Hadoop 生态集群供给** `scripts/env/hadoop-cluster-up.sh`：
   Hadoop 3.3.6 **发行版**（NN/RM/3×NM）+ Hive 3.1 + Spark 3.4，
   支持 `fs.defaultFS=ceph://` 与「HDFS 为主 + ceph 为辅」两种配置切换。
   本阶段只需集群可用 + `hadoop fs -ls ceph:///` 通过（生态用例在 T11）。
3. **CI 流水线**（`.github/workflows/`）：
   - `pr.yml`：L0 + L1，托管 runner，≤ 10 min；
   - `merge.yml`：+ L2 契约，self-hosted runner 或容器化单节点 Ceph
     （`scripts/ci/ceph-single-node.sh`），≤ 30 min；
   - `nightly.yml`：占位（T09–T10 填内容），含报告归档与 flaky 统计。
4. **L0 质量门禁**（pom 插件 + 脚本）：Checkstyle、SpotBugs(+findsecbugs)、
   JaCoCo（阈值见 TEST-PLAN §2，未达标 fail build）、OWASP dependency-check、
   license 检查、`scripts/ci/artifact-check.sh`（连续两次 `make-dist.sh` 产物
   sha256 一致 + `readelf -d` 校验发布 so 无构建机 RUNPATH）。
5. **L1 单测补强**：实现 TEST-CASES.md `UT-01`–`UT-20`。
6. **L2 契约扩展**：接入 Hadoop 官方基类套件 `CT-01`–`CT-05`
   （`FSMainOperationsBaseTest`、`FileContextMainOperationsBaseTest`、
   `FileContextCreateMkdirBaseTest`、`FileContextPermissionBase`、`FileContextURIBase`），
   全部沿用现有 `CEPH_CONTRACT_TEST=1` 门控；暴露的失败**只登记不修**
   （产品缺陷建单交 T09，测试适配问题当场修）。
7. **契约在 E2 重跑**：`CT-06`（三副本非调试构建）、`CT-07`（子目录挂载）、
   `CT-08`（最小 caps 用户），差异登记。

## 交付物

- `scripts/env/{ceph-cluster-up,ceph-cluster-down,hadoop-cluster-up,fingerprint}.sh`
- `scripts/ci/{ceph-single-node,artifact-check}.sh`、`.github/workflows/{pr,merge,nightly}.yml`
- pom 新增插件配置（checkstyle/spotbugs/jacoco/dependency-check/license）
- 新增单测 20 例、新增契约测试类 5 个
- `docs/TEST-ENV.md`：E1–E4 环境规格、访问方式、重建方法、指纹归档约定
- PROGRESS.md 登记：新增用例数、E2 上的契约结果差异表、暴露缺陷清单

## 验收标准

1. `scripts/env/ceph-cluster-up.sh` 从零一键产出 `HEALTH_OK` 的 3 副本集群，
   `fingerprint.sh` 输出归档；销毁重建可重复执行；
2. E2 上现有 9 套契约 + 新增 5 套官方套件全部执行完毕，通过率与差异逐条登记，
   且 **lockdep workaround 在生产构建上确认不需要**（结论回写 DEPLOY.md §6）；
3. `mvn clean verify` 在无集群环境仍全绿（新增用例正确 skip）；覆盖率达
   行 ≥ 80% / 分支 ≥ 70%、`CephFileSystem` 行 ≥ 85%，未达标时构建失败；
4. PR 门禁流水线 ≤ 10 min、合并门禁 ≤ 30 min，各跑通 3 次；
5. `artifact-check.sh` 通过（产物可重现 + so 无构建机 RUNPATH，或明确登记为
   待 T12 解决的遗留项）。

## 边界与禁止事项

- **不修产品代码缺陷**（除非阻塞测试执行且 < 15 分钟可修）：契约扩展暴露的语义
  问题一律建单交 T09；
- 不做故障注入、性能、生态用例（T09–T11）；
- 不改 `CephFsProto` / `CephConfigKeys` 冻结接口；
- E2/E3 的密钥与 keyring 不得入库。
