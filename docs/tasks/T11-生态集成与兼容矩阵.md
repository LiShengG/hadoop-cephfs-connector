# T11: Ecosystem integration and compatibility matrix

## Scope

Complete the stable ecosystem and compatibility test definitions using real component entry points,
then publish evidence-backed support conclusions for Hadoop, YARN, Hive, Spark, Tez, DistCp, HBase,
Flink, security shapes, and mixed filesystems.

## Non-goals

- Treating a representative query as completion of a scale, failure, or authorization case.
- Claiming compatibility for versions that have no dated report.
- Running security/version changes in the shared E3 environment without isolation and rollback.

## Acceptance criteria

- SP-01–SP-08 have final evidence-backed classifications and current limitations are linked.
- Every ecosystem P0 case has a result; P1 cases pass or have an approved waiver; P2 cases have a
  support conclusion.
- Unsupported behavior fails clearly and does not silently create incorrect data.
- Both Ceph-default and HDFS-default MapReduce shapes pass their required cases.
- Spark checkpoint recovery and required commit/format cases meet their definitions.
- COMPAT P0 cases pass and remaining required cases pass or have explicit support exclusions.
- A support matrix links to reports and lets operators identify supported combinations and limits.
