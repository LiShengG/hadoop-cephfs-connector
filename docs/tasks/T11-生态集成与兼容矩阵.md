# T11 — 生态集成与兼容矩阵

## 目标

补上 v1.0.0 最大的证据空白：连接器**从未在任何 Hadoop 生态组件下运行过**
（T06/T07 的验证均为 `FsShell` 等效方式）。本阶段在真实 Hadoop 发行版集群上跑通
MapReduce / YARN / Spark / Hive / DistCp，并给出 Hadoop、JDK、Ceph、OS 四维兼容矩阵结论。

## 前置依赖

T08 DONE（E3 Hadoop 生态集群 + E4 矩阵镜像可用）；T09 无 S1/S2 未关闭缺陷。
必读：`docs/TEST-PLAN.md` §9、§11；`docs/TEST-CASES.md` ECO-*/COMPAT-* 两节。

## 工作内容

1. **MapReduce / YARN**（ECO-01–ECO-05）：
   - wordcount、TeraSort 输入输出均 `ceph://`；
   - `fs.defaultFS=ceph://` 全局替换 HDFS：staging 目录、JobHistory、
     `/user/<user>` 家目录自动创建全链路；
   - **split 本地性**：验证 `getFileBlockLocations` 返回的 OSD 主机确实影响调度，
     记录本地性命中率（与全 localhost 降级情形对照）；
   - FileOutputCommitter v1/v2 的提交路径（`_temporary` 大量 rename）正确性与耗时；
   - YARN 日志聚合走 `FileContext`/`CephFs`——同时观测 NM 长跑下的 mount/会话累积。
2. **Spark 3.4**（ECO-06/07）：Parquet/ORC 读写、event log、checkpoint。
3. **Hive 3.1**（ECO-08）：外部表、`INSERT`、动态分区；记录分区扫描的
   `listStatus` 耗时（与 T10 的 N+1 结论相互印证）。
4. **DistCp**（ECO-09–ECO-11）：HDFS→Ceph、Ceph→Ceph、`-update` 增量；
   重点结论化 **`getFileChecksum` 返回 null 对 `-update`/校验的实际影响**（附录 A-5）。
5. **共存**（ECO-12）：同一集群 HDFS 与 `ceph://` 双 scheme 并用，
   验证 classpath 与 native 库无冲突。
6. **HBase 评估**（ECO-13，非承诺项）：基于 T10 的 `hflush` 延迟数据决定是否实测；
   无论是否实测，都要给出"支持/不支持/待评估"的书面结论。
7. **兼容矩阵**（COMPAT-01–COMPAT-12）：`scripts/env/compat-matrix.sh` 驱动
   E4 镜像逐格执行 L2 契约套件 + 一条端到端冒烟；
   **COMPAT-09（libcephfs.jar 与 jni so 版本错配）为 P0 负向用例**——失败必须发生得早
   且错误可诊断，不得运行到中途才崩。
8. 结果沉淀到 `docs/COMPAT.md`（绿/黄/红三态 + 豁免理由），
   并把发行版安装路径的真实结论回写 DEPLOY.md（补 T07 遗留 4）。

## 验收标准

1. ECO-01–ECO-12 全部执行且通过（ECO-13 至少有书面结论）；每个场景保留
   作业 ID、日志片段与数据一致性校验结果；
2. `fs.defaultFS=ceph://` 的 MR 全链路跑通（含 JobHistory 可查）；
3. YARN 日志聚合可用，且 NM 24h 观测的 mount/会话数据已记录（与 T12 长稳呼应）；
4. DistCp 三个方向均通过，`-update` 语义结论明确并写入文档；
5. COMPAT 矩阵 P0 格子全绿，P1 格子全绿或有书面豁免，COMPAT-09 负向用例
   表现符合"早失败 + 可诊断"；
6. DEPLOY.md 的发行版安装路径经真实 Hadoop 3.3.6 发行版实测（不再是 FsShell 等效）。

## 边界与禁止事项

- 不实现产品增强（如 `getFileChecksum`）：结论与建议进附录 A；
- 不做性能调优与长稳（T10/T12）；生态场景中的性能数据只作记录，
  正式基线以 T10 为准；
- 不引入对生态组件源码的修改；配置层面的适配须写入 DEPLOY.md；
- E4 镜像不得内置任何真实密钥。
