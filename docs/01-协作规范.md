# 多 Agent 协作规范

适用于本项目全部子任务 agent（T01–T07）。

## 1. 每个 agent 的启动流程

1. 通读 `docs/00-顶层架构设计.md`（必读，尤其 §3 冻结接口与 §4 语义差异表）；
2. 通读自己的任务书 `docs/tasks/TXX-*.md`；
3. 查看 `PROGRESS.md` 中前序任务的「交接说明」，确认前置验收全部达成；
4. 若前置条件不满足：**停止并在 PROGRESS.md 登记阻塞**，不要越权替前序任务补课
   （小于 15 分钟可修复的例外，修复后登记）。

## 2. 工作边界

- **只做本任务书「工作内容」列出的事项**；发现任务书之外的必要工作，登记到
  PROGRESS.md 的「遗留/移交事项」，由后续任务或人工决策处理。
- 不修改前序任务已交付并验收的公共接口签名（`CephFsProto`、`CephConfigKeys` 等）。
  确需修改时：在 PROGRESS.md 写明原因与影响面，做最小修改，并同步更新架构文档相应条目。
- 不修改 `/home/lsh/code/ceph` 与 `/home/lsh/code/hadoop-3.3.6-src` 的源码
  （T01 允许调整 ceph 的 cmake 构建配置，但不改源码）。
- 临时文件放各自 scratchpad，不污染工程目录。

## 3. 完成时的交接动作（缺一不可）

1. 自查任务书「验收标准」逐条通过，附验证命令与关键输出；
2. 在 `PROGRESS.md` 追加一节，模板：

```markdown
## TXX <任务名> — <状态: DONE/BLOCKED>（YYYY-MM-DD）
- 验收结果：逐条 ✅/❌ + 验证命令
- 交付物清单：文件路径列表
- 与设计文档的偏差：无 / <描述 + 原因>
- 遗留/移交事项：无 / <给后续任务的具体说明>
- 环境变更：无 / <如新装依赖、集群状态变化>
```

3. `git commit`（工程目录 `hadoop-cephfs-connector` 在 T01 初始化为 git 仓库），
   提交信息格式：`TXX: <一句话摘要>`。

## 4. 通用技术约定

- 代码：Java 11 语法但保持保守；包名 `org.apache.hadoop.fs.ceph`；
  日志用 slf4j（`LoggerFactory`），与 Hadoop 一致；
- 测试命名：单元测试 `Test*.java`，需真实集群的测试 `ITest*.java`；
- 需要真实集群的测试一律受 `CEPH_CONTRACT_TEST=1` 环境变量门控，保证
  `mvn test` 在无集群环境绿色通过；
- 所有 shell 可复现步骤写成脚本放 `hadoop-cephfs-connector/scripts/`，不要只留在会话里。
