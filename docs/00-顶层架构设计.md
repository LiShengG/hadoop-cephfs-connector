# Hadoop CephFS 连接器 — 顶层架构设计

> 版本：v1.0（2026-07-05）
> 状态：**已冻结**。各子任务 agent 以本文档为准；如实现中发现本文档与实际 API 不符，
> 在 PROGRESS.md 登记偏差并小范围修正，不得擅自更改分层结构与公共接口签名。

---

## 1. 目标与范围

### 1.1 目标

为 Hadoop 3.3.6 提供 CephFS 16.2.14 (Pacific) 存储后端：

- 实现 `org.apache.hadoop.fs.FileSystem` 子类 `CephFileSystem`（`FileSystem.get()` 路径，
  MapReduce / Hive / Spark / `hadoop fs` CLI 使用的主入口）；
- 实现 `org.apache.hadoop.fs.AbstractFileSystem` 子类 `CephFs`（`FileContext` 路径，
  YARN NodeManager 等使用），通过 `DelegateToFileSystem` 委托给 `CephFileSystem`，
  即"AbstractFileSystem API"方案落地方式；
- URI scheme：`ceph://`，支持设为 `fs.defaultFS`；
- 通过 Hadoop 官方 FileSystem 契约测试（明确声明不支持的语义除外）；
- 在本机 vstart 集群上完成端到端验证。

### 1.2 非目标（本期不做）

- Kerberos / Hadoop 委托 Token 集成（仅支持 cephx 认证）；
- `concat()`、`truncate()` 之外的扩展 API（XAttr、ACL、快照可作为后续迭代）；
- CephFS 多文件系统（multi-fs）选择、多活 MDS 调优；
- Hadoop 2.x 兼容。

## 2. 总体架构

### 2.1 分层结构

```
┌─────────────────────────────────────────────────────────┐
│  Hadoop 生态（MR / Hive / Spark / YARN / hadoop fs CLI） │
└───────────────┬─────────────────────┬───────────────────┘
        FileSystem API          FileContext API
                │                     │
┌───────────────▼──────────┐ ┌────────▼────────────────────┐
│ CephFileSystem           │ │ CephFs                      │
│ extends FileSystem       │◄┤ extends DelegateToFileSystem│  ① Hadoop 接口层
└───────────────┬──────────┘ └─────────────────────────────┘
                │  持有 1 个 CephFsProto 实例
┌───────────────▼──────────────────────────────────────────┐
│ CephFsProto（抽象类：定义连接器需要的全部 CephFS 原语）   │  ② 抽象层
│   └── CephTalker（生产实现，封装 com.ceph.fs.CephMount）  │     （可 mock）
└───────────────┬──────────────────────────────────────────┘
                │
┌───────────────▼──────────────────────────────────────────┐
│ CephInputStream / CephOutputStream（基于 fd 的流）        │  ③ 流层
└───────────────┬──────────────────────────────────────────┘
                │ JNI
┌───────────────▼──────────────────────────────────────────┐
│ libcephfs.jar (com.ceph.fs.CephMount) + libcephfs_jni.so │  ④ 原生绑定层
│                 → libcephfs.so → Ceph 集群 (MON/MDS/OSD) │
└──────────────────────────────────────────────────────────┘
```

### 2.2 分层理由

- **①与②分离**：`CephFileSystem` 只做 Hadoop 语义适配（路径解析、异常映射、
  rename/delete 语义修正），不直接触碰 JNI。所有 CephFS 调用收敛到 `CephFsProto`，
  单元测试可用 mock（Mockito）替换，无需真实集群。
- **④ 复用 Ceph 官方 Java 绑定**：`ceph/src/java` 自带 `com.ceph.fs.CephMount`
  （JNI 封装 libcephfs C API），与 16.2.14 的 libcephfs.so 严格同源，避免自写 JNI。
- **AbstractFileSystem 用 DelegateToFileSystem**：与 Hadoop 内置做法一致
  （参考 `hadoop-3.3.6-src` 中 `LocalFs`、`RawLocalFs` 的写法），零重复逻辑。

## 3. 关键接口设计（冻结）

### 3.1 CephFsProto 抽象层

T02 定义，后续任务只增不改已冻结签名。方法与 libcephfs 原语一一对应（节选核心，
完整清单见 T02 任务书）：

```java
abstract class CephFsProto {
  abstract void initialize(URI uri, Configuration conf) throws IOException;
  abstract void shutdown() throws IOException;

  // 元数据
  abstract CephStatVFS statfs(Path path) throws IOException;
  abstract void lstat(Path path, CephStat stat) throws IOException; // 不存在时抛 FileNotFoundException
  abstract String[] listdir(Path path) throws IOException;          // 非目录返回 null
  abstract void mkdirs(Path path, int mode) throws IOException;
  abstract void rmdir(Path path) throws IOException;
  abstract void unlink(Path path) throws IOException;
  abstract void rename(Path src, Path dst) throws IOException;
  abstract void setattr(Path path, CephStat stat, int mask) throws IOException;
  abstract void chmod(Path path, int mode) throws IOException;

  // 数据
  abstract int open(Path path, int flags, int mode) throws IOException;
  abstract int open(Path path, int flags, int mode, int stripeUnit,
                    int stripeCount, int objectSize, String dataPool) throws IOException;
  abstract long lseek(int fd, long offset, int whence) throws IOException;
  abstract int read(int fd, byte[] buf, long size, long offset) throws IOException;
  abstract int write(int fd, byte[] buf, long size, long offset) throws IOException;
  abstract void fstat(int fd, CephStat stat) throws IOException;
  abstract void close(int fd) throws IOException;
  abstract void flush(int fd) throws IOException;                   // ceph fsync
  abstract void ftruncate(int fd, long size) throws IOException;

  // 数据局部性
  abstract CephFileExtent getFileExtent(int fd, long offset) throws IOException;
  abstract InetAddress getOsdAddress(int osd) throws IOException;
}
```

> 说明：`CephStat` / `CephStatVFS` / `CephFileExtent` 直接使用 `com.ceph.fs.*` 中的类型。
> T02 实现时须以 `ceph/src/java/java/com/ceph/fs/CephMount.java`（16.2.14 实际源码）
> 为准核对每个方法签名，发现不一致以源码为准并登记 PROGRESS.md。

### 3.2 CephFileSystem 对外行为

| Hadoop API | 实现要点 |
|---|---|
| `initialize(uri, conf)` | 加载配置 → `CephTalker.initialize()`（mount）→ 记录 workingDir=`/user/<user>` |
| `getFileStatus` | `lstat` 映射为 `FileStatus`（含 mode→FsPermission、uid/gid→用户名尽力映射） |
| `listStatus` | `listdir` + 逐项 `lstat`；路径不存在抛 `FileNotFoundException` |
| `mkdirs` | 递归创建（libcephfs `mkdirs` 原生支持），已存在同名**文件**时返回 false/抛异常 |
| `delete(path, recursive)` | 文件→`unlink`；目录→ 若非空且 `!recursive` 抛 `PathIsNotEmptyDirectoryException`，否则**Java 侧递归**删除（libcephfs `rmdir` 仅支持空目录） |
| `rename(src, dst)` | 见 §4 语义修正 |
| `open` | `open(O_RDONLY)` → `CephInputStream` |
| `create` | 处理 overwrite/父目录创建/块大小/副本参数 → `open(O_WRONLY|O_CREAT[|O_EXCL])` → `CephOutputStream` |
| `append` | `open(O_WRONLY|O_APPEND)` → `CephOutputStream` |
| `getFileBlockLocations` | `get_file_extent` + OSD 地址 → `BlockLocation[]`（数据局部性） |
| `getDefaultBlockSize` | 取 `ceph.object.size`（默认 64MB），并在 `create` 时作为 object layout 下发 |
| `setPermission` / `setOwner` / `setTimes` | `chmod` / `setattr` |
| `getUri` / `getScheme` | `ceph` |

### 3.3 流实现要点

- `CephInputStream extends FSInputStream`：实现 `seek/getPos/seekToNewSource/read`，
  内部维护预读缓冲（默认 `ceph.client.buffer.size`），支持 `PositionedReadable`
  （`FSInputStream` 默认实现基于 seek，可先用默认实现）。
- `CephOutputStream extends OutputStream implements Syncable`：内部写缓冲；
  `hflush()/hsync()` → `proto.flush(fd)`（ceph fsync）；`close()` 幂等。
- 每个流独占一个 fd；`CephMount` 由 `FileSystem` 实例内共享（libcephfs 线程安全，
  但 Java 侧对同一 mount 的调用统一经 `CephTalker`，fd 级操作无须加锁，
  mount 级操作如 rename 依赖 libcephfs 自身锁）。

## 4. Hadoop ↔ POSIX(CephFS) 语义差异与修正（实现者必读）

| # | 差异点 | 修正策略 |
|---|---|---|
| 1 | POSIX `rename` 会静默覆盖已存在目标文件；Hadoop `rename` 要求返回 false | rename 前 `lstat(dst)`：dst 为已存在文件→返回 false；dst 为已存在目录→改为移动到 `dst/srcName`（与 HDFS 行为一致） |
| 2 | `rmdir` 仅删空目录 | `delete(recursive=true)` 在 Java 侧后序遍历递归删除 |
| 3 | Hadoop 大量 API 用返回值 false 表错误、用异常表环境错误 | 在 `CephFileSystem` 层统一转换：`FileNotFoundException`、`FileAlreadyExistsException`、`ParentNotDirectoryException` 等按 Hadoop FS 规范（见 hadoop 源码 `filesystem.md` 规范文档）抛出 |
| 4 | CephFS 无"副本数"概念（由 pool 决定） | `setReplication` 返回 false；`getFileStatus` 中 replication 报告 pool size（可简化为固定值，T06 契约测试时定稿） |
| 5 | 块大小是 layout（stripe/object size），仅创建时可设 | `create` 时把 blockSize 参数映射为 object_size/stripe_unit；已有文件报告其实际 layout |
| 6 | uid/gid 是数字，Hadoop 需要用户名 | 尽力映射：与当前进程 uid 相同→当前用户名，否则报告数字字符串；不做 NSS 查询 |
| 7 | `workingDir` | 纯 Java 侧维护（不用 `ceph_chdir`），初始 `/user/<ugi.shortUserName>` |
| 8 | atime/mtime 精度 | CephFS 纳秒 → Hadoop 毫秒，直接截断 |

## 5. 配置项设计（冻结，常量定义在 CephConfigKeys）

| 配置键 | 默认值 | 说明 |
|---|---|---|
| `fs.ceph.impl` | — | `org.apache.hadoop.fs.ceph.CephFileSystem`（用户 core-site.xml 配置） |
| `fs.AbstractFileSystem.ceph.impl` | — | `org.apache.hadoop.fs.ceph.CephFs` |
| `fs.defaultFS` | — | 形如 `ceph://mon-host:6789/` 或 `ceph:///`（mon 从 ceph.conf 读取） |
| `ceph.conf.file` | null | ceph.conf 路径；vstart 环境用 `/home/lsh/code/ceph/build/ceph.conf` |
| `ceph.conf.options` | null | 分号分隔的额外 ceph 配置，如 `client_mount_timeout=30` |
| `ceph.auth.id` | null | cephx 用户 id（如 `admin`） |
| `ceph.auth.keyring` | null | keyring 文件路径 |
| `ceph.root.dir` | `/` | 挂载后视为 FS 根的 CephFS 子目录 |
| `ceph.object.size` | 67108864 (64MB) | 新文件默认 object size，兼作 Hadoop blockSize |
| `ceph.data.pools` | null | 新文件写入的 data pool（逗号分隔，取第一个匹配） |
| `ceph.localize.reads` | true | 读时优先本地 OSD 副本 |
| `ceph.client.buffer.size` | 4194304 (4MB) | 流的读/写缓冲大小 |

URI 优先级：`ceph://host:port/path` 中的 host:port 若存在则覆盖 ceph.conf 的 mon 地址
（写入 conf 项 `mon_host`）；无 authority 时完全依赖 `ceph.conf.file`。

## 6. 构建与测试策略

### 6.1 依赖与构建

- Maven 工程，`hadoop-common:3.3.6` 作用域 `provided`；
- `libcephfs.jar`（T01 产出）通过 `mvn install:install-file` 装入本地仓库，
  坐标定为 `com.ceph:libcephfs:16.2.14`；
- `libcephfs_jni.so` 为运行时原生依赖，测试用
  `-Djava.library.path=<路径>`（同时保证 `LD_LIBRARY_PATH` 含 `ceph/build/lib`）。

### 6.2 三级测试

1. **单元测试**（无集群）：mock `CephFsProto`，验证语义修正逻辑（rename/delete/异常映射）。
2. **契约测试**（需 vstart）：继承 Hadoop `AbstractFSContractTestBase` 系列
   （hadoop-common test-jar），`ceph.xml` 声明支持的语义；受环境变量
   `CEPH_CONTRACT_TEST=1` 门控，默认 skip。
3. **集成验证**（需 vstart）：`hadoop fs -mkdir/-put/-cat/-ls/-mv/-rm -r` 全链路 +
   大文件（>2×object size）读写一致性（md5 比对）。

### 6.3 vstart 集群操作参考

```bash
cd /home/lsh/code/ceph/build
../src/vstart.sh -d -n -x --without-dashboard   # -n 全新集群；日常重启去掉 -n
bin/ceph -s                                     # 确认 HEALTH_OK / fs 就绪
bin/ceph fs ls                                  # 确认 cephfs 文件系统存在
../src/stop.sh                                  # 停止
```

vstart 的 `ceph.conf` 与 `keyring` 位于 `ceph/build/` 下，连接器测试直接引用。

## 7. 风险清单

| 风险 | 影响 | 预案 |
|---|---|---|
| Java 绑定构建失败（cmake WITH_CEPHFS_JAVA 依赖缺失） | 阻塞全部后续任务 | T01 备选路径：`javac` 直接编译 `src/java/java` + 手动编译 `native/libcephfs_jni.cc`（链接已有 libcephfs.so） |
