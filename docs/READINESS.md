## 4. 关键路径与阻塞

1. **E2/E3 供给是第一阻塞**：`.26/.44/.28` 三节点资源已可达，E1 已在 `.26` 恢复；
   但 C/D/E/F 四个维度（共 55% 权重）仍依赖 E2（3 副本、非 Debug、多 MDS）与 E3
   （Hadoop 发行版集群）。当前尚缺分布式 Ceph 部署、第二网络、`.28` 旧 OSD 处置确认、
   Hadoop/YARN 服务化与环境指纹脚本，完成度仍停在 ~30%。
2. **当前最高优先级产品缺陷**：SP-04A2 已证实普通 `FileContext.rename` 因 6789/-1
   默认端口不一致而失败；先修复并接入 FileContext 契约，再判断 SP-04B 并发语义。
3. **已触发产品增强**：SP-01/02/03/06A/08B 均成立，需处理 owner/group 名字映射、
   chown 失败语义和安全口径；完成前不得声明多用户 MR/Hive/YARN 或 Kerberos 受支持。
4. **零成本可做**：I8 版本重定位——挡住"用户按 GA 预期使用"这类最坏误用。

## 5. 更新规则

- 每阶段（SPIKE/T08–T12）收尾时，由该阶段 agent 更新「当前」列与证据链接，并在
  PROGRESS.md 登记本表的变化；
- **§1 总览表与进度条在 README.md 首页有一份副本，必须同步更新**（含表头的更新日期），
  两处不一致时以本文件为准；
- 「当前」百分比必须有可追溯证据（用例 ID / 报告路径 / commit），**不得凭感觉打分**；
- 权重调整须在发布评审上决定并记录理由，不得为了让数字好看而改权重。
